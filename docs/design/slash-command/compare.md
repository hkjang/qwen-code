# Qwen Code 명령 모듈 재구성 계획

## 1. 목표 정의

이 계획은 다음 원칙을 유일한 전제로 삼고 있습니다.

* **코드 구조는 Claude Code를 그대로 복사할 필요가 없습니다.**
* **단, 명령 시스템의 핵심 기능, 사용 경험, 상호 작용 경험은 Claude Code와 95% 일치해야 합니다.**

여기서 "정렬(Alignment)"은 사용자가 직접 체감할 수 있는 다음 기능들을 의미합니다.

1. 명령 소스(Source) 재정의
2. 명령 도움말 및 탐색 가능성
3. 명령 자동 완성 및 입력 중간의 슬래시 명령 경험
4. ACP/비대화형 가용성 확장
5. 프롬프트 명령/스킬에 대한 모델 호출 능력

이번 리팩토링은 `SlashCommand` 인터페이스에 필드 몇 개를 추가하거나 수정하는 사소한 작업이 아닙니다. 명령 모듈을 단순히 "대화형 UI를 위한 보조 기능"에서 "대화형/ACP/비대화형/모델 호출을 아우르는 통합 명령 플랫폼"으로 업그레이드하는 과정입니다.

***

## 2. 재작성 후 결론

기존 Qwen 명령 시스템의 문제점은 기능이 아예 없어서가 아니라 다음과 같은 한계가 있기 때문입니다.

1. 대화형 기본 경로에만 치중되어 있음.
2. 타입 모델이 너무 단순하여 Claude 수준의 제품 기능을 담아내기 어려움.
3. ACP/비대화형 모드가 하드코딩된 화이트리스트에 의존하여 확장성이 매우 낮음.
4. 명령 소스가 구분되어 있어도 사용자에게 일관된 개념 모델을 제공하지 못함.
5. 프롬프트 명령과 모델 스킬 시스템이 파편화되어 있음.

따라서 새로운 솔루션은 다음 네 가지를 동시에 해결해야 합니다.

1. **Claude Code의 역량을 따라잡기**
2. **Qwen의 통합 결과 모델(Unified Result Model)이 갖는 엔지니어링적 이점 유지**
3. **통합 레지스트리/리졸버/실행기/어댑터 아키텍처 구축**
4. **도움말, 자동 완성, ACP 명령 목록 및 문서가 동일한 메타데이터 세트를 공유하도록 보장**

***

## 3. 재구성 원칙

### 3.1 기능 정렬이 구현 정렬보다 우선함

다음 사항의 차이는 허용됩니다:
* 내부 클래스 이름
* 모듈 분할 방식
* 실행기(Executor) 구현 방식
* 효과/결과(Effect/Result) 구조

다음 사항의 차이는 허용되지 않습니다:
* 명령 소스의 범위가 대폭 축소되는 것
* 명령 도움말 및 자동 완성 경험이 크게 떨어지는 것
* ACP/비대화형 가용성이 현저히 낮은 것
* 프롬프트 명령과 모델 스킬의 통합 수준이 낮은 것

상충 관계가 발생할 경우 우선순위는 다음과 같습니다:
1. 사용자 경험 정렬
2. 명령 능력(Capability) 정렬
3. 스키마(Schema) 일관성 정렬
4. 내부 구현의 단순성

### 3.2 Qwen의 통합 결과 모델 보존

Claude의 구현을 기계적으로 복사하는 것은 권장하지 않습니다. Qwen의 현재 통합 결과 모델은 UI 렌더링, 승인/확인, 도구 예약, 프롬프트 제출 등을 모드에 관계없이 처리하는 데 이점이 있으므로 이를 유지하되, Claude 수준의 기능을 수행할 수 있도록 업그레이드해야 합니다.

### 3.3 타입, 소스, 모드 및 가시성의 완전한 분리

새로운 명령 모델은 최소한 다음 차원을 구분해야 합니다.
1. **타입(Type)**: 명령을 어떻게 실행하는가
2. **소스(Source)**: 명령이 어디서 왔는가
3. **모드(Mode)**: 어떤 운영 환경에서 사용 가능한가
4. **가시성(Visibility)**: 사용자에게 보이는가, 모델에게 보이는가

## 4. Claude Code와 정렬이 필요한 역량

### 4.1 명령 타입
Qwen은 다음 세 가지 타입을 명시적으로 지원해야 합니다.
1. `prompt`
2. `local`
3. `local-jsx`

### 4.2 명령 소스
다음 소스들을 포함해야 합니다.
1. 내장 명령 (Built-in)
2. 번들 스킬 (Bundled Skill)
3. 스킬 디렉토리 명령 (Custom)
4. 워크플로 명령 (Workflow)
5. 플러그인 명령 (Plugin)
... 등등

### 4.3 명령 메타데이터
`argumentHint`, `whenToUse`, `examples`, `sourceLabel`, `userInvocable`, `modelInvocable`, `supportedModes` 등의 필드를 보강합니다.

### 4.4 경험 역량
자동 완성 배지, 매개변수 힌트, 최근 사용 순 정렬, 입력 중간 슬래시 감지, 그룹화된 도움말 등을 구현합니다.

***

## 5. 단계별 구현 계획

### 1단계: 기반 재구성
통합 레지스트리, 리졸버, 실행기 및 모드별 어댑터 아키텍처를 구축하고 메타데이터 모델을 정의합니다.

### 2단계: 핵심 명령 마이그레이션
`/model`, `/permissions`, `/mcp` 등 주요 명령을 "대화형 셸 + 로컬 하위 명령" 구조로 재구성하여 모든 모드에서 사용 가능하게 만듭니다.

### 3단계: 모델 기능 개방
`SkillTool`이 통합 레지스트리를 사용하도록 하여, 다양한 소스의 프롬프트 명령을 모델이 도구로 호출할 수 있게 합니다.

### 4단계: 사용자 경험 고도화
최근 사용 순 정렬, 소스 배지, 인수 힌트, 입력 중간 슬래시 경험 등 Claude Code 수준의 디테일을 완성합니다.

***

## 6. 최종 결론

이 리팩토링의 핵심은 "기존 SlashCommand에 필드 몇 개를 추가하는 것"이 아니라, **Qwen의 내부 아키텍처 스타일을 유지하면서 사용자 경험 측면에서 Claude Code와 95% 일치하는 명령 플랫폼을 제공하는 것**입니다.
