# Qwen 코드 구성

> \[!팁]
>
> **인증/API 키:**인증(API Key, Alibaba Cloud Coding Plan) 및 인증 관련 환경 변수(예:`OPENAI_API_KEY`)에 문서화되어 있습니다.**[입증](../configuration/auth)**.

> \[!메모]
>
> **새로운 구성 형식에 대한 참고 사항**: 형식`settings.json`파일이 새롭고 더욱 체계적인 구조로 업데이트되었습니다. 이전 형식은 자동으로 마이그레이션됩니다.
> Qwen Code는 환경 변수, 명령줄 인수 및 설정 파일을 포함하여 동작을 구성하는 여러 가지 방법을 제공합니다. 이 문서에서는 다양한 구성 방법과 사용 가능한 설정을 간략하게 설명합니다.

## 구성 레이어

구성은 다음 우선 순위에 따라 적용됩니다(낮은 숫자가 높은 숫자로 재정의됨).

| 수준 | 구성 소스      | 설명                                  |
| -- | ---------- | ----------------------------------- |
| 1  | 기본값        | 애플리케이션 내에서 하드코딩된 기본값                |
| 2  | 시스템 기본값 파일 | 다른 설정 파일로 재정의할 수 있는 시스템 전체 기본 설정    |
| 3  | 사용자 설정 파일  | 현재 사용자에 대한 전역 설정                    |
| 4  | 프로젝트 설정 파일 | 프로젝트별 설정                            |
| 5  | 시스템 설정 파일  | 다른 모든 설정 파일을 재정의하는 시스템 전체 설정        |
| 6  | 환경변수       | 잠재적으로 로드되는 시스템 전체 또는 세션별 변수`.env`파일 |
| 7  | 명령줄 인수     | CLI를 시작할 때 전달되는 값                   |

## 설정 파일

Qwen Code는 지속적인 구성을 위해 JSON 설정 파일을 사용합니다. 이러한 파일의 위치는 4개입니다.

| 파일 유형      | 위치                                                                                                                                                                                                                                       | 범위                                                                                                                          |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 시스템 기본값 파일 | 리눅스:`/etc/qwen-code/system-defaults.json`<br>윈도우:`C:\ProgramData\qwen-code\system-defaults.json`<br>맥OS:`/Library/Application Support/QwenCode/system-defaults.json` <br>경로는 다음을 사용하여 재정의될 수 있습니다.`QWEN_CODE_SYSTEM_DEFAULTS_PATH`환경 변수. | 시스템 전체 기본 설정의 기본 계층을 제공합니다. 이러한 설정은 우선 순위가 가장 낮으며 사용자, 프로젝트 또는 시스템 재정의 설정에 의해 재정의됩니다.                                       |
| 사용자 설정 파일  | `~/.qwen/settings.json`(어디`~`홈 디렉토리입니다).                                                                                                                                                                                                 | 현재 사용자의 모든 Qwen Code 세션에 적용됩니다.                                                                                             |
| 프로젝트 설정 파일 | `.qwen/settings.json`프로젝트의 루트 디렉터리 내.                                                                                                                                                                                                    | 해당 특정 프로젝트에서 Qwen Code를 실행할 때만 적용됩니다. 프로젝트 설정은 사용자 설정보다 우선합니다.                                                              |
| 시스템 설정 파일  | 리눅스：`/etc/qwen-code/settings.json` <br>윈도우:`C:\ProgramData\qwen-code\settings.json` <br>맥OS:`/Library/Application Support/QwenCode/settings.json`<br>경로는 다음을 사용하여 재정의될 수 있습니다.`QWEN_CODE_SYSTEM_SETTINGS_PATH`환경 변수.                     | 모든 사용자에 대해 시스템의 모든 Qwen Code 세션에 적용됩니다. 시스템 설정은 사용자 및 프로젝트 설정보다 우선합니다. 기업의 시스템 관리자가 사용자의 Qwen Code 설정을 제어하는 ​​데 유용할 수 있습니다. |

> \[!메모]
>
> **설정의 환경 변수에 대한 참고 사항:**귀하의 문자열 값`settings.json`파일은 다음 중 하나를 사용하여 환경 변수를 참조할 수 있습니다.`$VAR_NAME`또는`${VAR_NAME}`통사론. 이러한 변수는 설정이 로드되면 자동으로 해결됩니다. 예를 들어 환경 변수가 있는 경우`MY_API_TOKEN`, 당신은 그것을 사용할 수 있습니다`settings.json`이와 같이:`"apiKey": "$MY_API_TOKEN"`.

### 구성 마이그레이션

Qwen Code는 기존 구성 설정을 새로운 형식으로 자동 마이그레이션합니다. 이전 설정 파일은 마이그레이션 전에 백업됩니다. 다음 설정의 이름이 음수(`disable*`)에서 양수로 (`enable*`) 우리:

| 이전 설정                                  | 새로운 설정                                      | 메모          |
| -------------------------------------- | ------------------------------------------- | ----------- |
| `disableAutoUpdate`+`disableUpdateNag` | `general.enableAutoUpdate`                  | 단일 설정으로 통합됨 |
| `disableLoadingPhrases`                | `ui.accessibility.enableLoadingPhrases`     |             |
| `disableFuzzySearch`                   | `context.fileFiltering.enableFuzzySearch`   |             |
| `disableCacheControl`                  | `model.generationConfig.enableCacheControl` |             |

> \[!메모]
>
> **부울 값 반전:**마이그레이션 시 부울 값이 반전됩니다(예:`disableAutoUpdate: true`된다`enableAutoUpdate: false`).

#### 다음에 대한 통합 정책`disableAutoUpdate`그리고`disableUpdateNag`

두 레거시 설정이 서로 다른 값으로 존재하는 경우 마이그레이션은 다음 정책을 따릅니다.**어느 하나** `disableAutoUpdate` **또는** `disableUpdateNag`\~이다`true`, 그 다음에`enableAutoUpdate`된다`false`:

| `disableAutoUpdate` | `disableUpdateNag` | 마이그레이션됨`enableAutoUpdate` |
| ------------------- | ------------------ | ------------------------- |
| `false`             | `false`            | `true`                    |
| `false`             | `true`             | `false`                   |
| `true`              | `false`            | `false`                   |
| `true`              | `true`             | `false`                   |

**max\_tokens(적응형 출력 토큰):**

언제`samplingParams.max_tokens`설정되지 않은 경우 Qwen Code는 적응형 출력 토큰 전략을 사용하여 GPU 리소스 사용을 최적화합니다.

1. 요청은 기본 제한으로 시작됩니다.**8K**출력 토큰
2. 응답이 잘리면(모델이 한계에 도달함) Qwen Code는 자동으로 다음을 사용하여 재시도합니다.**64K**토큰
3. 부분 출력은 삭제되고 재시도의 전체 응답으로 대체됩니다.

이는 사용자에게 투명합니다. 에스컬레이션이 발생하면 재시도 표시가 잠시 표시될 수 있습니다. 응답의 99%가 5,000개 토큰 미만이므로 재시도가 거의 발생하지 않습니다(요청의 1% 미만).

이 동작을 재정의하려면 다음 중 하나를 설정하십시오.`samplingParams.max_tokens`설정에서 또는`QWEN_CODE_MAX_OUTPUT_TOKENS`환경 변수.

**컨텍스트창 크기:**

선택한 모델의 기본 컨텍스트 창 크기를 재정의합니다. Qwen Code는 일정한 대체 값과 함께 모델 이름 일치를 기반으로 내장된 기본값을 사용하여 컨텍스트 창을 결정합니다. 공급자의 유효 컨텍스트 제한이 Qwen Code의 기본값과 다른 경우 이 설정을 사용합니다. 이 값은 요청별 토큰 제한이 아닌 모델의 가정된 최대 컨텍스트 용량을 정의합니다.

**양식:**

선택한 모델에 대해 자동 감지된 입력 양식을 재정의합니다. Qwen Code는 모델 이름 패턴 일치를 기반으로 지원되는 형식(이미지, PDF, 오디오, 비디오)을 자동으로 감지합니다. 자동 감지가 올바르지 않은 경우 이 설정을 사용하십시오. 예를 들어 활성화하려면`pdf`지원하지만 인식되지 않는 모델의 경우. 체재:`{ "image": true, "pdf": true, "audio": true, "video": true }`. 키를 생략하거나 다음으로 설정하세요.`false`지원되지 않는 유형의 경우.

**맞춤헤더:**

모든 API 요청에 사용자 정의 HTTP 헤더를 추가할 수 있습니다. 이는 요청 추적, 모니터링, API 게이트웨이 라우팅 또는 여러 모델에 서로 다른 헤더가 필요한 경우에 유용합니다. 만약에`customHeaders`에 정의되어 있습니다`modelProviders[].generationConfig.customHeaders`, 직접 사용됩니다. 그렇지 않은 경우 헤더는`model.generationConfig.customHeaders`사용됩니다. 두 수준 간에는 병합이 발생하지 않습니다.

그만큼`extra_body`필드를 사용하면 API로 전송된 요청 본문에 사용자 정의 매개변수를 추가할 수 있습니다. 이는 표준 구성 필드에서 다루지 않는 공급자별 옵션에 유용합니다.**참고: 이 필드는 OpenAI 호환 공급자(`openai`,`qwen-oauth`). Anthropic 및 Gemini 제공자에 대해서는 무시됩니다.**만약에`extra_body`에 정의되어 있습니다`modelProviders[].generationConfig.extra_body`, 직접 사용됩니다. 그렇지 않으면 다음 값`model.generationConfig.extra_body`사용됩니다.

#### 파일 검색 성능 문제 해결

파일 검색 시 성능 문제가 발생하는 경우(예:`@`완료), 특히 파일 수가 매우 많은 프로젝트에서 권장되는 순서대로 시도해 볼 수 있는 몇 가지 사항은 다음과 같습니다.

1. **사용`.qwenignore`:**만들기`.qwenignore`참조할 필요가 없는 다수의 파일(예: 빌드 아티팩트, 로그,`node_modules`). 크롤링되는 총 파일 수를 줄이는 것이 성능을 향상시키는 가장 효과적인 방법입니다.
2. **퍼지 검색 비활성화:**파일을 무시하는 것만으로는 충분하지 않은 경우 설정을 통해 퍼지 검색을 비활성화할 수 있습니다.`enableFuzzySearch`에게`false`당신의`settings.json`파일. 이는 더 빠르고 간단하며 퍼지가 아닌 일치 알고리즘을 사용합니다.
3. **재귀 파일 검색 비활성화:**최후의 수단으로 설정을 통해 재귀 파일 검색을 완전히 비활성화할 수 있습니다.`enableRecursiveFileSearch`에게`false`. 이는 프로젝트의 재귀 크롤링을 방지하므로 가장 빠른 옵션입니다. 그러나 이는 다음을 사용할 때 파일의 전체 경로를 입력해야 함을 의미합니다.`@`완료.

**쉘 명령 우회 방지:**

다음에 대한 권한 규칙`Read`,`Edit`, 그리고`WebFetch`에이전트가 동등한 셸 명령을 실행할 때도 적용됩니다. 예를 들어,`Read(./.env)`에 있습니다`deny`, 에이전트는 다음을 통해 이를 우회할 수 없습니다.`cat .env`쉘 명령에서. 지원되는 셸 명령은 다음과 같습니다.`cat`,`grep`,`curl`,`wget`,`cp`,`mv`,`rm`,`chmod`, 그리고 더 많은 것. 알 수 없거나 안전한 명령(예:`git`)은 파일/네트워크 규칙의 영향을 받지 않습니다.

**레거시 설정에서 마이그레이션:**

| 레거시 설정          | 동등한`permissions`규칙         | 메모                                        |
| --------------- | -------------------------- | ----------------------------------------- |
| `tools.allowed` | `permissions.allow`        | 첫 번째 로드 시 자동 마이그레이션                       |
| `tools.exclude` | `permissions.deny`         | 첫 번째 로드 시 자동 마이그레이션                       |
| `tools.core`    | `permissions.allow`(허용 목록) | 자동 마이그레이션됨 목록에 없는 도구는 레지스트리 수준에서 비활성화됩니다. |

**예시 구성:**

```json
{
  "permissions": {
    "allow": ["Bash(git *)", "Bash(npm run *)", "Read(//Users/alice/code/**)"],
    "ask": ["Bash(git push *)", "Edit"],
    "deny": ["Bash(rm -rf *)", "Read(.env)", "WebFetch(malicious.com)"]
  }
}
```

#### mcp서버

사용자 정의 도구를 검색하고 사용하기 위해 하나 이상의 MCP(Model-Context Protocol) 서버에 대한 연결을 구성합니다. Qwen Code는 사용 가능한 도구를 검색하기 위해 구성된 각 MCP 서버에 연결을 시도합니다. 여러 MCP 서버가 동일한 이름의 도구를 노출하는 경우 도구 이름 앞에는 구성에서 정의한 서버 별칭이 붙습니다(예:`serverAlias__actualToolName`) 충돌을 피하기 위해. 시스템은 호환성을 위해 MCP 도구 정의에서 특정 스키마 속성을 제거할 수 있습니다. 다음 중 적어도 하나`command`,`url`, 또는`httpUrl`제공되어야 합니다. 여러 개를 지정한 경우 우선 순위는 다음과 같습니다.`httpUrl`, 그 다음에`url`, 그 다음에`command`.

| 재산                                      | 유형     | 설명                                                                                                                                    | 선택 과목 |
| --------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `mcpServers.<SERVER_NAME>.command`      | 끈      | 표준 I/O를 통해 MCP 서버를 시작하기 위해 실행하는 명령입니다.                                                                                                | 예     |

## 환경변수 &`.env`파일

환경 변수는 특히 중요한 정보(예: 토큰) 또는 환경 간에 변경될 수 있는 설정에 대해 애플리케이션을 구성하는 일반적인 방법입니다.

Qwen 코드는 다음에서 환경 변수를 자동으로 로드할 수 있습니다.`.env`파일.
인증 관련 변수(예:`OPENAI_*`) 및 권장 사항`.qwen/.env`접근하다, 보아라**[입증](../configuration/auth)**.

> \[!팁]
>
> **환경 변수 제외:**일부 환경 변수(예:`DEBUG`그리고`DEBUG_MODE`)은 프로젝트에서 자동으로 제외됩니다.`.env`CLI 동작에 대한 간섭을 방지하기 위해 기본적으로 파일을 저장합니다. 변수의`.qwen/.env`파일은 제외되지 않습니다. 다음을 사용하여 이 동작을 사용자 정의할 수 있습니다.`advanced.excludedEnvVars`당신의 설정`settings.json`파일.

## 명령줄 인수

CLI를 실행할 때 직접 전달된 인수는 해당 특정 세션에 대한 다른 구성을 재정의할 수 있습니다.

샌드박스 이미지 선택의 우선순위는 다음과 같습니다.`--sandbox-image`>`QWEN_SANDBOX_IMAGE`>`tools.sandboxImage`> 내장된 기본 이미지.

### 명령줄 인수 표

| 논쟁                           | 별명   | 설명                                                                                                                                               | 가능한 값                               | 메모                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--model`                    | `-m` | 이 세션에 사용할 Qwen 모델을 지정합니다.                                                                                                                        | 모델명                                 | 예:`npm start -- --model qwen3-coder-plus`                                                                                                                                                                                                                                                                                                                                         |
| `--prompt`                   | `-p` | 프롬프트를 명령에 직접 전달하는 데 사용됩니다. 이는 비대화형 모드에서 Qwen Code를 호출합니다.                                                                                        | 프롬프트 텍스트                            | 스크립팅 예제의 경우`--output-format json`구조화된 출력을 얻기 위한 플래그입니다.                                                                                                                                                                                                                                                                                                                           |
| `--prompt-interactive`       | `-i` | 제공된 프롬프트를 초기 입력으로 사용하여 대화형 세션을 시작합니다.                                                                                                            | 프롬프트 텍스트                            | 프롬프트는 대화형 세션 이전이 아닌 대화형 세션 내에서 처리됩니다. stdin에서 입력을 파이핑할 때는 사용할 수 없습니다. 예:`qwen -i "explain this code"`                                                                                                                                                                                                                                                                             |
| `--system-prompt`            |      | 이 실행에 대해 내장된 기본 세션 시스템 프롬프트를 재정의합니다.                                                                                                             | 프롬프트 텍스트                            | 다음과 같은 로드된 컨텍스트 파일`QWEN.md`이 재정의 후에도 계속 추가됩니다. 와 결합 가능`--append-system-prompt`.                                                                                                                                                                                                                                                                                                   |
| `--append-system-prompt`     |      | 이 실행에 대한 기본 세션 시스템 프롬프트에 추가 지침을 추가합니다.                                                                                                           | 프롬프트 텍스트                            | 내장 프롬프트 및 로드된 컨텍스트 파일 다음에 적용됩니다. 와 결합 가능`--system-prompt`. 보다[헤드리스 모드](../features/headless)예를 들어.                                                                                                                                                                                                                                                                                |

## 컨텍스트 파일(계층적 교육 컨텍스트)

CLI에 대한 구성이 엄격하지는 않지만*행동*, 컨텍스트 파일(기본값은`QWEN.md`하지만 다음을 통해 구성 가능`context.fileName`설정)은*교육적 맥락*("메모리"라고도 함). 이 강력한 기능을 사용하면 프로젝트별 지침, 코딩 스타일 가이드 또는 관련 배경 정보를 AI에 제공하여 AI의 응답을 사용자의 요구에 더욱 맞춤화되고 정확하게 만들 수 있습니다. CLI에는 로드된 컨텍스트 파일 수를 표시하는 바닥글의 표시기와 같은 UI 요소가 포함되어 활성 컨텍스트에 대한 정보를 지속적으로 제공합니다.

* **목적:**이러한 Markdown 파일에는 상호 작용 중에 Qwen 모델이 인식할 수 있는 지침, 지침 또는 컨텍스트가 포함되어 있습니다. 시스템은 이러한 교육적 맥락을 계층적으로 관리하도록 설계되었습니다.

### 예제 컨텍스트 파일 콘텐츠(예:`QWEN.md`)

다음은 TypeScript 프로젝트 루트의 컨텍스트 파일에 포함될 수 있는 내용에 대한 개념적 예입니다.

```
# Project: My Awesome TypeScript Library

## General Instructions:
- When generating new TypeScript code, please follow the existing coding style.
- Ensure all new functions and classes have JSDoc comments.
- Prefer functional programming paradigms where appropriate.
- All code should be compatible with TypeScript 5.0 and Node.js 20+.

## Coding Style:
- Use 2 spaces for indentation.
- Interface names should be prefixed with `I` (e.g., `IUserService`).
- Private class members should be prefixed with an underscore (`_`).
- Always use strict equality (`===` and `!==`).

## Specific Component: `src/api/client.ts`
- This file handles all outbound API requests.
- When adding new API call functions, ensure they include robust error handling and logging.
- Use the existing `fetchWithRetry` utility for all GET requests.

## Regarding Dependencies:
- 피해야 할 사항 introducing new external dependencies unless absolutely necessary.
- If a new dependency is required, please state the reason.
```

이 예에서는 일반적인 프로젝트 컨텍스트, 특정 코딩 규칙, 심지어 특정 파일이나 구성 요소에 대한 참고 사항까지 제공할 수 있는 방법을 보여줍니다. 컨텍스트 파일이 더 관련성이 높고 정확할수록 AI가 더 나은 지원을 제공할 수 있습니다. 프로젝트별 컨텍스트 파일은 규칙과 컨텍스트를 설정하는 데 적극 권장됩니다.

* **계층적 로딩 및 우선순위:**CLI는 컨텍스트 파일(예:`QWEN.md`) 여러 위치에서. 이 목록의 아래쪽(더 구체적)에 있는 파일의 콘텐츠는 일반적으로 위쪽(더 일반적인) 파일의 콘텐츠를 재정의하거나 보완합니다. 정확한 연결 순서와 최종 컨텍스트는 다음을 사용하여 검사할 수 있습니다.`/memory show`명령. 일반적인 로딩 순서는 다음과 같습니다.
  1. **전역 컨텍스트 파일:**
     * 위치:`~/.qwen/<configured-context-filename>`(예:`~/.qwen/QWEN.md`사용자 홈 디렉터리에 있음).
     * 범위: 모든 프로젝트에 대한 기본 지침을 제공합니다.
  2. **프로젝트 루트 및 조상 컨텍스트 파일:**
     * 위치: CLI는 현재 작업 디렉터리에서 구성된 컨텍스트 파일을 검색한 다음 각 상위 디렉터리에서 프로젝트 루트(`.git`폴더) 또는 홈 디렉터리입니다.
     * 범위: 전체 프로젝트 또는 프로젝트의 상당 부분과 관련된 컨텍스트를 제공합니다.
* **연결 및 UI 표시:**발견된 모든 컨텍스트 파일의 내용은 연결되어(원본과 경로를 나타내는 구분 기호와 함께) 시스템 프롬프트의 일부로 제공됩니다. CLI 바닥글은 로드된 컨텍스트 파일 수를 표시하여 활성 교육 컨텍스트에 대한 빠른 시각적 신호를 제공합니다.
* **콘텐츠 가져오기:**다음을 사용하여 다른 Markdown 파일을 가져와서 컨텍스트 파일을 모듈화할 수 있습니다.`@path/to/file.md`통사론. 자세한 내용은 다음을 참조하세요.[메모리 가져오기 프로세서 문서](../configuration/memory).
* **메모리 관리 명령:**
  * 사용`/memory refresh`구성된 모든 위치에서 모든 컨텍스트 파일을 강제로 다시 검색하고 다시 로드합니다. 이는 AI의 교육적 맥락을 업데이트합니다.
  * 사용`/memory show`현재 로드된 결합된 교육 컨텍스트를 표시하여 AI가 사용하는 계층 구조와 콘텐츠를 확인할 수 있습니다.
  * 참조[명령 문서](../features/commands)자세한 내용은`/memory`명령 및 해당 하위 명령(`show`그리고`refresh`).

이러한 구성 레이어와 컨텍스트 파일의 계층적 특성을 이해하고 활용함으로써 AI의 메모리를 효과적으로 관리하고 Qwen Code의 응답을 특정 요구 사항과 프로젝트에 맞게 조정할 수 있습니다.

## 모래 상자

Qwen Code는 샌드박스 환경 내에서 잠재적으로 안전하지 않은 작업(예: 셸 명령 및 파일 수정)을 실행하여 시스템을 보호할 수 있습니다.

[모래 상자](../features/sandbox)기본적으로 비활성화되어 있지만 다음과 같은 몇 가지 방법으로 활성화할 수 있습니다.

* 사용`--sandbox`또는`-s`깃발.
* 환경`QWEN_SANDBOX`환경 변수.
* 다음을 사용할 때 샌드박스가 활성화됩니다.`--yolo`또는`--approval-mode=yolo`기본적으로.

기본적으로 사전 빌드된`qwen-code-sandbox`도커 이미지.

프로젝트별 샌드박싱 요구사항의 경우 다음에서 사용자 정의 Dockerfile을 생성할 수 있습니다.`.qwen/sandbox.Dockerfile`프로젝트의 루트 디렉터리에 있습니다. 이 Dockerfile은 기본 샌드박스 이미지를 기반으로 할 수 있습니다.

```
FROM qwen-code-sandbox
# Add your custom dependencies or configurations here
# For example:
# RUN apt-get update && apt-get install -y some-package
# COPY ./my-config /app/my-config
```

언제`.qwen/sandbox.Dockerfile`존재하면 사용할 수 있습니다`BUILD_SANDBOX`사용자 정의 샌드박스 이미지를 자동으로 빌드하기 위해 Qwen 코드를 실행할 때 환경 변수:

```
BUILD_SANDBOX=1 qwen -s
```

## 사용 통계

Qwen Code 개선을 돕기 위해 당사는 익명화된 사용 통계를 수집합니다. 이 데이터는 CLI 사용 방법을 이해하고, 일반적인 문제를 식별하고, 새로운 기능의 우선 순위를 지정하는 데 도움이 됩니다.

**우리가 수집하는 것:**

* **도구 호출:**호출된 도구의 이름, 성공 여부, 실행하는 데 걸리는 시간을 기록합니다. 우리는 도구에 전달된 인수나 도구에서 반환된 데이터를 수집하지 않습니다.
* **API 요청:**각 요청에 사용된 모델, 요청 기간, 성공 여부를 기록합니다. 우리는 프롬프트나 응답의 내용을 수집하지 않습니다.
* **세션 정보:**활성화된 도구, 승인 모드 등 CLI 구성에 대한 정보를 수집합니다.

**당사가 수집하지 않는 것:**

* **개인 식별 정보(PII):**우리는 귀하의 이름, 이메일 주소, API 키와 같은 어떠한 개인정보도 수집하지 않습니다.
* **프롬프트 및 응답 내용:**우리는 귀하의 프롬프트 내용이나 모델의 응답을 기록하지 않습니다.
* **파일 내용:**CLI에서 읽거나 쓴 파일의 내용은 기록하지 않습니다.

**선택 해제 방법:**

귀하는 언제든지 다음 설정을 통해 사용 통계 수집을 거부할 수 있습니다.`usageStatisticsEnabled`재산`false`아래에`privacy`귀하의 카테고리`settings.json`파일:

```
{
  "privacy": {
    "usageStatisticsEnabled": false
  }
}
```

> \[!메모]
>
> 사용 통계가 활성화되면 이벤트가 Alibaba Cloud RUM 수집 엔드포인트로 전송됩니다.
